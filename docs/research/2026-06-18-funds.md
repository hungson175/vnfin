### Fmarket - Fund List (filter)
- **Host:** `api.fmarket.vn`
- **Data:** FUND LIST: all VN open-ended mutual funds distributed on Fmarket (equity/bond/balanced) with code, shortName, internal id, current nav (VND/unit), lastYearNav, managementFee, avgAnnualReturn, owner (fund manager), firstIssueAt. Supports filtering by fundAssetTypes (e.g. STOCK) and free-text searchField.
- **Auth:** None (no token/cookie required)
- **History:** Current snapshot (list of funds); per-fund history via NAV endpoint below.
- **Coverage:** The historical response listed multiple VN open-ended funds and accepted the documented asset-class filter. Exact total, provider codes, and row identities are redacted from this repository.
- **Format:** JSON: `{status:200, data:{total:<redacted>, page, pageSize, rows:[{id,code,shortName,name,nav,lastYearNav,managementFee,avgAnnualReturn,owner:{name,shortName},...}]}}`. nav is VND per fund unit.
- **Endpoints:** POST https://api.fmarket.vn/res/products/filter  body(JSON): {"types":["NEW_FUND","TRADING_FUND"],"sortField":"navTo6Months","sortOrder":"DESC","page":1,"pageSize":100,"isIpo":false,"fundAssetTypes":[],"searchField":""}  (fundAssetTypes can be ["STOCK"]; searchField does name/code search)
- **Terms:** fmarket.vn/robots.txt disallows only `/assets/params/` and `/blog|help-center/ket-qua-tim-kiem/*`
  (search pages); `api.fmarket.vn` has no robots.txt. The route historically powered the fund-browse
  UI, but commercial distribution permission was not established.
```bash
curl -4 -s -m 25 -X POST 'https://api.fmarket.vn/res/products/filter' -H 'Content-Type: application/json' --data '<redacted historical body>'
```
_proof:_ the historical response was a successful JSON envelope with a populated total and rows; exact totals, IDs, NAV values, fund names, and search examples are redacted. The parser contract retains only field names and types.

### Fmarket - NAV History
- **Host:** `api.fmarket.vn`
- **Data:** NAV HISTORY time series for a single fund (daily/business-day frequency). One row per available NAV date.
- **Auth:** None
- **History:** Multi-year, from fund inception, was observed for more than one synthetic-redacted product. Exact row counts, product identities, first dates, and NAV values are redacted. Use `isAllData:1` for full history, or `fromDate`/`toDate` (`YYYY-MM-DD`) to window it in the historical parser contract.
- **Coverage:** Multiple Fmarket funds were observed historically (exact count redacted); use the
  internal id from the fund-list endpoint as `productId` in the historical parser contract.
- **Format:** JSON: {status:200, data:[{id, navDate:'YYYY-MM-DD', nav: <float VND/unit>, productId, createdAt:<epoch ms or null>}]}. nav = NAV per fund unit in VND.
- **Endpoints:** POST `https://api.fmarket.vn/res/product/get-nav-history` with a historical JSON
  body containing `isAllData`, a redacted `productId`, and redacted `fromDate`/`toDate` values.
  (Omit `isAllData` and set the date fields to fetch a historical date range.)
- **Terms:** Same host/ToS note as fund-list. No auth. navDate is string YYYY-MM-DD; createdAt epoch millis (sometimes null for old rows).
```bash
# Historical request shape only; provider identity and date window are redacted.
curl -4 -s -m 25 -X POST 'https://api.fmarket.vn/res/product/get-nav-history' \
  -H 'Content-Type: application/json' \
  --data '{"isAllData":1,"productId":"<redacted>","fromDate":"<redacted>","toDate":"<redacted>"}'
```
_proof:_ the historical request returned a populated NAV array for a provider product. Exact
product IDs, row counts, dates, and NAV values are redacted; this file retains only the response
shape and the source-gap/legal conclusion.

### Fmarket - Fund Detail (Holdings / Allocation)
- **Host:** `api.fmarket.vn`
- **Data:** HOLDINGS & ALLOCATION for a single fund: top holdings (per-stock weight + industry + last price), asset-class allocation (STOCK/CASH/BOND %), and industry/sector allocation %. Plus full fund metadata (fees, inception, description, manager).
- **Auth:** None
- **History:** Latest disclosed snapshot (holdings updated periodically, updateAt epoch ms on each row). Not a time series.
- **Coverage:** The historical detail route was observed for multiple Fmarket funds. Exact total,
  product identities, and row counts are redacted. Equity holdings were in
  `productTopHoldingList`; per-bond holdings were in `productTopHoldingBondList`; asset-class split
  was in `productAssetHoldingList`. This preserves the #173 schema conclusion without retaining a
  real provider row.
- **Format:** JSON: `data.productTopHoldingList:[{stockCode, netAssetPercent, industry, price, type:'STOCK', updateAt}]`, `data.productTopHoldingBondList:[{stockCode:<redacted>, netAssetPercent, industry, price:null, type:'BOND', updateAt}]`, `data.productAssetHoldingList:[{assetType:{code:'STOCK'|'CASH'|'BOND',name}, assetPercent, updateAt}]`, `data.productIndustriesHoldingList:[{industry, assetPercent}]`. Percentages 0-100. (No `productBondHoldingList` key — the bond array is `productTopHoldingBondList`.)
- **Endpoints:** GET `https://api.fmarket.vn/res/products/{id}` where `{id}` is the internal product
  identifier from the historical fund-list response; exact IDs are redacted.
- **Terms:** Same host/ToS note as above. No auth. Holdings reflect last periodic fund disclosure.
```bash
curl -4 -s -m 25 'https://api.fmarket.vn/res/products/<redacted-product-id>' -H 'Accept: application/json'
```
_proof:_ historical detail responses contained holdings, asset-class, and industry arrays with
  numeric percentage fields; exact provider rows, symbols, weights, IDs, and names are redacted.
